# Optional secondary guest network

These are site-specific templates after base virtualization acceptance. Install the compatible Kubernetes NMState Operator, create its `NMState` instance, and confirm it is ready before applying the policy. `eno2` is an example secondary NIC on each selected worker with VLAN 120 allowed on its switch trunk. Check NIC names, MTU, switch port security, and presence of the network on every potential destination. Keep the machine uplink and OpenShift-managed bridge intact.

Apply the node label `lab.example.test/guest-uplink=true` to a verified canary worker, then apply the [policy](10-bridge-policy.yaml) from the cluster CLI. Check `oc get nncp,nnce` and require successful enactment before expanding to more workers. Review other NMState policies for conflicts. Then apply the [NAD](20-network-attachment.yaml) in `virt-smoke`. For a VM in that namespace, add `{name: guest-vlan, bridge: {}}` to the VM interface list and `{name: guest-vlan, multus: {networkName: guest-vlan}}` to the networks list. Constrain that VM to workers with the verified uplink label. Before starting the VM, verify the bridge resource `bridge.network.kubevirt.io/br-guest` is advertised on each eligible worker. Update the NAD annotation if you rename the bridge. Configure the guest with approved DHCP or static addressing and prove VLAN-specific reachability.

This is a guest secondary network. A dedicated migration transport follows the separate version-specific HyperConverged procedure. [OpenShift Virtualization 4.20 networking](https://docs.redhat.com/en/documentation/openshift_container_platform/4.20/html/virtualization/networking), [Postinstallation network setup](https://docs.redhat.com/en/documentation/openshift_container_platform/4.20/html/virtualization/postinstallation-configuration)
