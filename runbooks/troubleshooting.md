# Troubleshooting by provisioning stage

Start with the last successful handoff and its time. Work outward from that point. Save a private copy of the relevant event or log with the resource name and error. Some logs and virtual-media URLs contain credentials or sensitive bootstrap material.

| Symptom | First observation | Command and environment | Interpretation | Next branch |
| --- | --- | --- | --- | --- |
| Bootstrap VM missing | Installer phase and whether domain was expected to be removed | RHEL provisioner · `virsh -c qemu:///system list --all`, `tail -n 100 "$INSTALL_DIR/.openshift_install.log"` | No domain before handoff can indicate download, libvirt access, bridge, or disk failure | Check `journalctl -u libvirtd -u virtqemud`, installer version, cache and local storage. After handoff verify API and phase before investigating teardown. |
| BMC authentication failure | BMH error and the Ironic log entry for the host | Cluster CLI · `oc -n openshift-machine-api describe bmh master-0`. Bootstrap VM · find Ironic with `sudo podman ps -a` and read its logs | Authentication or authorization errors differ from TLS, routing and wrong system path | Match credential reference and account policy privately. Validate the system ID, permissions, trust and firmware against inventory. |
| Virtual ISO unreachable | Redfish authenticated, then InsertMedia or fetch failed | Bootstrap VM · `sudo ss -lntp`. RHEL provisioner · `virsh -c qemu:///system domiflist "$BOOTSTRAP_DOMAIN"`. Check BMC event and site ACL logs | The reverse BMC-to-server connection can fail independently, including HTTPS trust or route | Compare the actual advertised URL, media port and listener with BMC network/firmware. After handoff check the service on the permanent control plane. |
| Wrong target disk or no match | IPA inventory and serial selected for deployment | Authorized physical console · `lsblk -d -o NAME,SIZE,MODEL,SERIAL,WWN` in an approved live environment. Cluster CLI · `oc -n openshift-machine-api describe bmh master-0` | Stale serial or RAID logical volume identity, changing kernel name, or ambiguous match | Pause retries using the site's change procedure, compare rack/controller records, and confirm the unique installation disk before any reprovisioning. |
| Ignition fetch failed | Does the host boot from the intended local disk with the expected address? | Authorized physical console · `journalctl -b -t ignition`, `getent hosts api-int.virt-lab.example.test`, `nc -vz api-int.virt-lab.example.test 22623` if installed | MCS path, DNS, routing, VIP ownership, clock or certificate can block a role fetch | Inspect the appropriate MCS listener and logs. Check role path without printing the Ignition body. Separately verify TCP 6443 after Ignition succeeds. |
| Worker missing or NotReady | Find the last populated BMH → Machine → Node reference | Cluster CLI · `oc -n openshift-machine-api get bmh,machines,machinesets -o wide`, `oc get nodes,csr` | Missing BMH consumer points to MachineSet/provider selection. Provisioned BMH without a Node points to first boot, MCS, API or kubelet. NotReady suggests runtime, network or configuration | Compare Machine conditions, inspect kubelet and CRI logs if authorized, check OVN/MCP/CSR state, and confirm identity before approving any certificate. |
| Ingress unhealthy | Router readiness, admitted Route, and its endpoints | Cluster CLI · `oc -n openshift-ingress get pods -o wide` and `oc -n ipi-smoke get route,svc,endpointslices`. Admin workstation · `dig +short "$ROUTE_HOST"`, `curl -v "https://$ROUTE_HOST/health"` | DNS or VIP path faults differ from TLS errors, no backend endpoints, or unexpected application response | Confirm ingress VIP and router placement, then compare Service port, readiness, endpoint and the app response. |
| VM migration blocked | VMI migratability condition and target scheduling events | Cluster CLI · `oc -n virt-smoke describe vmi virt-smoke`, `oc -n virt-smoke get vmim,pvc,pods -o wide`, `oc -n virt-smoke get events --sort-by=.lastTimestamp` | Storage access, node constraints, CPU incompatibility, device passthrough, network binding or blocked transport can stop migration | Compare VMI conditions, shared CSI topology and PVC mode first, then target resources, CPUs and migration network. Re-run eligibility and reachability checks after fixing the cause. |
